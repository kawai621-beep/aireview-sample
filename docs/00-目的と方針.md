# 00. 目的と方針

## 1. リポジトリの目的

本リポジトリは、**AIコードレビューツールのレビュー性能を比較・評価する**ために作成されたサンプルアプリケーションです。

具体的には、意図的に多数の問題（セキュリティ脆弱性、N+1問題、可読性の低下、メンテナンス性の欠如など）を埋め込んだ TypeScript 製 Web アプリケーションを用意し、同じ Pull Request を複数のレビューツールにレビューさせることで「どのツールが、どの問題を、どの程度正確に検出できるか」を定量的・定性的に比較します。

> **注意**: 本リポジトリのコードは **意図的に問題を含んでいます**。絶対に本番環境で運用しないでください。また、本コードをコピーして実プロジェクトに転用しないでください。

## 2. 比較対象ツール

| ツール | 概要 |
|---|---|
| **CodeRabbit** | GitHub/GitLab の Pull Request に自動でAIレビューを投稿するサービス。差分ベースで要約・指摘・修正提案を行う。 |
| **cubic.dev** | GitHub の Pull Request に対してAIコードレビューを行うサービス。チームのレビュー傾向を学習し、コンテキストを考慮した指摘を行うことを特徴とする。 |

両者とも **Pull Request の差分（diff）を入力としてレビューを行う** ため、比較の公平性を保つには「同じ差分を両ツールに見せる」ことが必須になります（詳細は [06-PR分割と比較フロー](./06-PR分割と比較フロー.md) を参照）。

## 3. 評価の前提とスコープ

### 3.1 評価の対象（What を比較するか）

- **検出率（Recall）**: 埋め込んだ問題のうち、どれだけを検出できたか
- **精度（Precision）**: 検出した指摘のうち、有意なもの（False Positive でない）の割合
- **指摘の質**: 修正提案の具体性・正確さ、リスクの説明の深さ、根拠の提示

### 3.2 スコープ外（本評価では測らないこと）

- ツールのセットアップの容易さ・料金・UI の使い勝手
- IDE 拡張や CLI など、PR 以外の経路でのレビュー機能
- 実行速度（レビュー完了までの時間）

### 3.3 公平性を保つための設計上の前提

- 両ツールに **全く同一の Pull Request 差分** を入力する（main ブランチを共通のベースにする）
- 埋め込む問題には **難易度のグラデーション** を持たせる（自明な問題から深い推論が必要な問題まで）
- 問題の混入によって **型エラーやビルドエラーが派生しない** ようにする（別のノイズとして扱われないため）
- 各 PR の差分は **適度なサイズ（概ね 500 行以内）** に保つ（巨大 diff による精度低下を避けるため）

## 4. 用語定義

### 4.1 セキュリティ・DB 関連

| 用語 | 説明 |
|---|---|
| **N+1 問題** | 一覧取得（1回）＋ 各要素ごとの個別取得（N回）で、DB クエリが N+1 回発生する非効率。 |
| **SQLi（SQL Injection）** | ユーザ入力を SQL 文に直接文字列結合することで、意図しない SQL を実行される脆弱性。 |
| **XSS（Cross-Site Scripting）** | ユーザ入力を適切にエスケープせず HTML に出力することで、悪意あるスクリプトを実行される脆弱性。 |
| **CSRF（Cross-Site Request Forgery）** | 認証済みユーザの意図しないリクエストを第三者が踏ませる攻撃。Cookie 認証との組み合わせで問題になる。 |
| **IDOR（Insecure Direct Object Reference）** | アクセス権のチェックなしに ID を指定してリソースにアクセスできる脆弱性。他ユーザのデータが見えてしまう。 |
| **JWT（JSON Web Token）** | ヘッダ・ペイロード・署名からなるトークン形式。`alg: none` 攻撃や秘密鍵漏洩が代表的な罠。 |
| **タイミング攻撃** | 処理時間の差から内部情報（パスワード等）を推測する攻撃。文字列比較の `===` で発生し得る。 |

### 4.2 レビュー評価指標

| 用語 | 説明 |
|---|---|
| **PR（Pull Request）** | 変更差分をレビュー対象として提出する仕組み。本評価では各 PR が1つのレビュー単位。 |
| **Recall（再現率）** | `検出した問題数 / 全埋め込み問題数`。見逃しが少ないほど高い。 |
| **Precision（適合率）** | `真陽性 / 全指摘数`。無関係な指摘（ノイズ）が少ないほど高い。 |
| **False Positive（FP）** | 問題ではないのに問題として指摘されたもの（誤検知）。Precision を下げる要因。 |
| **難易度** | 各問題につけた「検出の難しさ」の指標。低（自明）／中（優秀なら検出）／高（深い推論が必要）。定義は [05-埋め込んだ問題一覧](./05-埋め込んだ問題一覧.md) を参照。 |
