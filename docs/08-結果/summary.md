## 3. 検出できた/できなかった問題の傾向

### cubic（Recall 93%）
- **広範・深い検出**: N+1（3種すべて）・SQLi・IDOR・レース（いいね競合・会員登録競合）・TZ・タイミング攻撃・入力バリデーションなど、高難易度を含む広範な問題を取りこぼさない。
- **見逃しは A7（レートリミット欠如）のみ**。D3（`any`多用）は `@ts-ignore`/デッドコードを指摘し部分点。
- **修正案が具体的**: bcrypt/argon2・DOMPurify・Prisma `increment`・UNIQUE制約など実装可能な修正を提示。

### CodeRabbit（Recall 56%）
- **得意**: 明確な Critical/Major の定番問題は的確に検出 — base64ハッシュ・ハードコード秘密・`alg:none`（CVE まで深掘り）・CORS・SQLi・IDOR・XSS・秘密のフロント埋め込み・stack/info 漏洩・リソースリーク 等。
- **苦手**: **N+1（3件すべて見逃し）・レース条件（いいね競合）・タイミング攻撃・入力バリデーション・並行登録の競合・長大関数・`any` 多用・コード重複** など「深い推論またはアーキテクチャ観点」の問題を多数見逃す。
- **深さの質**: 検出した問題（特に `alg:none`）では ast-grep・Web query で CVE/仕様まで調査する深さがあり、修正案の AI エージェントプロンプトを添える。

## 4. 結論

本サンプル（ブログ/CMS、27問題）では **cubic が検出力（Recall 93% vs 56%）・得点（51 vs 31）で明確に上回る**結果。

- **cubic** は「パターン検出可能な定番問題」だけでなく「文脈推論や並行性・アーキテクチャ観点が必要な問題」まで幅広く捉え、修正案も具体的位置を示す。一方ツール両者が取りこぼした A7（レートリミット）のような運用系の指摘は、本サンプルでは両者とも得手でなかった。
- **CodeRabbit** はセキュリティ系の定番問題（とくに `alg:none` の CVE 調査）で深い分析を見せるが、N+1・レース・タイミング攻撃・長大関数・型/重複などを見逃す傾向がある。

なお、CodeRabbit は本検証中に Pro Plus 1シートのレートリミットに複数回抵触し、レビュー完了まで半日以上と時間を要した（cubic は4 PR 合計 1時間強で完了）。運用上の安定性・スループットも含めた比較要素となる。

## 5. 備考: 公平性

- 両ツールとも同一の PR 差分（`base...head`）を入力とした。PR 本文は中立な機能説明のみ。
- CodeRabbit は Organization UI 設定（Review profile: CHILL）+ `.coderabbit.yaml`（`base_branches` で stacked PR の base を許可）。cubic は既定設定。
- 難易度・採点は `docs/05` `docs/07` に基づく。難易度は予測値であり、両ツールの実際の挙動を見て事後に見直してよい。
