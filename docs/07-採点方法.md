# 07. 採点方法

本ドキュメントでは、CodeRabbit と cubic.dev のレビュー結果を採点するための指標・ルーブリック・集計フォーマットを定義する。

> 採点の対象となる問題の一覧は [`05-埋め込んだ問題一覧.md`](./05-埋め込んだ問題一覧.md) を参照。

---

## 1. 評価指標

3つの指標で総合的に評価する。

### 1.1 Recall（検出率）

埋め込んだ問題のうち、ツールが検出できた割合。

```
Recall = 検出した問題数（スコア1以上）/ 埋め込んだ問題数（27件）
```

Recallが高いほど「見逃しが少ない」。難易度別（低/中/高）にも算出する（後述）。

### 1.2 Precision（精度）

ツールが挙げた指摘のうち、有意な指摘（真陽性）の割合。

```
Precision = 真陽性の指摘数 / ツールが挙げた全指摘数
```

Precisionが低い = ノイズ（無意味な指摘）が多い。実運用ではレビュー疲れ・修正誘導のリスクになる。

### 1.3 指摘の質（qualitative）

検出の有無だけでなく、指摘内容の質を評価する:

- **修正案の具体性**: 正しいコード例を提示しているか。実行可能で安全な修正か。
- **リスク説明の深さ**: 影響範囲・攻撃シナリオ・深刻度を正しく説明しているか。
- **根拠の提示**: OWASP/CVE/ベストプラクティス/公式ドキュメントなど、裏付けを示しているか。

---

## 2. 検出スコア ルーブリック（0/1/2点）

各問題について、ツールの出力を以下のルーブリックで採点する。

| スコア | 判定基準 |
|---|---|
| **2点** | 問題の**本質**を検出し、かつ**妥当な修正案**を提示している。影響・根拠も適切。 |
| **1点** | 問題の存在には言及したが、修正案が**浅い/不適切**、または深刻度を**誤認**している。 |
| **0点** | 検出なし（見逃し）。 |

- 同じ問題に対して複数の指摘があった場合は、最も良いものを採用する。
- 「問題の存在には触れたが別の理由付け」の場合は1点。
- 単なるスタイル指摘で問題の本質に触れないものは0点。

---

## 3. False Positive（FP）の扱い

[`05-埋め込んだ問題一覧.md`](./05-埋め込んだ問題一覧.md) に含まれない指摘のうち、**有意でない**ものを False Positive としてカウントする。

- **FPに含める例**: 存在しない問題の指摘、誤った修正案、過剰なスタイル指摘、本質と無関係な一般論。
- **FPに含めない例**: 埋め込んだ問題とは別だが、**技術的に正しい・有意な指摘**（例: 本リポジトリで意図的に作っていない別の問題を偶然見つけた場合）。これは「ボーナス発見」として記録し、Precisionの分母からは除外してよい。

```
Precision = 真陽性 / (真陽性 + False Positive)
```

FPが多いほど Precision が下がり、総合評価を下げる要素になる。

---

## 4. 難易度別の重み付け

埋め込む問題には難易度（低/中/高）が設定されている（ [`05-埋め込んだ問題一覧.md`](./05-埋め込んだ問題一覧.md) ）。高難易度の検出ほど高く評価する。

### 重み付け案

| 難易度 | 重み | 満点（スコア2）の加重得点 | 意味 |
|---|---|---|---|
| 低 | 1.0 | 2.0 | 両ツールとも取れるべき自明な問題 |
| 中 | 1.5 | 3.0 | 優秀なツールなら検出できる問題 |
| 高 | 2.0 | 4.0 | 深い推論が必要な、識別力を反映する問題 |

### 加重検出スコア

```
加重スコア = Σ (各問題のスコア/2 × 満点加重得点)
```

### 難易度別 Recall

各難易度で独立して Recall を算出する:

```
Recall_低 = 低難易度の検出数(スコア1以上) / 低難易度の問題数
Recall_中 = 中難易度の検出数(スコア1以上) / 中難易度の問題数
Recall_高 = 高難易度の検出数(スコア1以上) / 高難易度の問題数
```

特に **Recall_高 の差** が両ツールの識別力の差を最もよく反映する。

## 6. 採点時の注意

- 採点は**問題の正解（実装時に意図的に埋め込んだ内容）**を把握した上で行う。バイアスを避けるため、可能ならブラインド採点（どのツールの出力か隠して採点）を検討する。
- ツールの指摘が複数の問題にまたがる場合、該当する問題IDすべてにスコアを付与してよい。
- 「検出したが修正案が逆に悪化させる」場合は0点または1点（修正案の有害性による）。
- 採点結果は事実ベースで記録し、振り返りとして両ツールの強弱を分析する。
